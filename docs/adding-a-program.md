# Adding a program

Everything below is what it actually took to add the GTK and Qt components, in
the order it had to happen. A program takes about half an hour end to end.

The running example is a notification-adjacent daemon called `mako`; substitute
your own.

---

## 1. Decide what belongs where

Two questions, and getting them wrong is the only expensive mistake here.

**Is it appearance or structure?** Colours, fonts, radii and spacing belong in
the [theme](themes.md), so every program shares them and a theme switch moves
them together. Anything about *this program's* behaviour — its position, its
timeouts, which modules it shows — belongs in
[`config.toml`](configuration.md), because it should survive a theme change.

**Does the program read one file?** Rice deploys by replacing a config path
with a symlink. A program that wants a directory, or that rewrites its own
configuration, does not fit the model and needs thinking about first.

---

## 2. Add the configuration

In `internal/config/config.go`:

```go
// Mako describes the notification daemon.
type Mako struct {
    Anchor      string `toml:"anchor"`
    DefaultTimeout int `toml:"default_timeout"`
}
```

Add it to `Config`, add `Mako bool` to `Components`, and add the case to
`Components.Enabled`. Then in `internal/config/load.go` add the name to
`Components.Names` — **in deployment order** — and to `Components.Any`.

Give it defaults in `internal/config/defaults.go`, including turning the
component on in `DefaultConfig` if it should be on by default.

---

## 3. Write the template

`templates/mako/config.tmpl`. Start it with the generated-by header every other
template has, so nobody edits the output by mistake:

```
# Generated by Rice {{ .Version }} for generation {{ .Generation }}.
# Theme: {{ .Theme.Name }}

background-color={{ .Colors.Surface }}
text-color={{ .Colors.Foreground }}
border-color={{ .Colors.BorderFocus }}
border-size={{ .UI.BorderWidth }}
font={{ font .Fonts.UIFamily .Fonts.UISize }}
anchor={{ .Mako.Anchor }}
```

The context and the whole function set are in [templates.md](templates.md).
Two rules worth repeating:

* Use the **semantic** colours (`.Colors.Primary`), not the ANSI palette,
  unless the program really is a terminal.
* Guard anything optional with `{{ with }}`. A key with nothing after it is not
  the same as an absent key, and several programs take an empty value
  literally.

Templates are embedded, so no build step is needed — but `templates/` is an
`embed.FS`, so a new directory only appears after a rebuild.

---

## 4. Write the adapter

`internal/adapter/mako/mako.go`. Four methods and a validator:

```go
func (Adapter) Name() string { return "mako" }

func (Adapter) Files() []adapter.File {
    return []adapter.File{
        {Template: "mako/config.tmpl", Path: "mako/config"},
    }
}

func (Adapter) ConfigPaths() []adapter.ManagedPath {
    return []adapter.ManagedPath{
        {Source: "mako/config", Target: "mako/config"},
    }
}

func (Adapter) ReloadMode() adapter.ReloadMode { return adapter.ReloadSignal }

func (Adapter) Validate(dir string) error { /* parse the generated file */ }
```

`Validate` should catch the mistake templates actually make — unbalanced
braces, invalid JSON, a line that is not `key=value`. It runs before a
generation is committed, so a broken template never reaches `current`.

If the *set* of files depends on configuration, implement `adapter.Configurable`
as well and return the narrowed set; see `internal/adapter/gtk`.

If the program needs a reload command, add it to `internal/reload`.

---

## 5. Register it

`internal/adapter` is not self-registering, on purpose: the registry is
explicit so nothing appears in a generation by accident. Add `mako.New()` to
the registry in:

* `internal/cli/app.go` — the real one
* `golden_test.go`
* `internal/session/session_test.go`
* `internal/tui/tui_test.go`

The tests fail loudly if you miss one: `Components.Names` will offer a name the
registry cannot resolve.

---

## 6. Make it editable and previewable

In `internal/session/programs.go`, add a `makoFields()` table and wire it into
`buildProgramFields`. Scalars only — the constructors are `pInt`, `pBool`,
`pText` and `pChoice`. That is all the editor needs; the fields appear
automatically.

In `internal/session/sandbox.go`, add an entry to `launches` so the program can
be previewed:

```go
"mako": {
    Binary: "mako",
    Args:   func(dir string) []string { return []string{"-c", filepath.Join(dir, "mako", "config")} },
},
```

If it cannot be previewed, say why in `Blocked` rather than leaving it out —
the editor shows the reason. If previewing it does something surprising, put
that in `Confirm`.

---

## 7. Accept the golden output

```bash
make golden      # go test ./... -update
git diff testdata/
```

Read the diff. It is the whole point of the golden files: you are confirming
that what you just wrote produces what you meant.

---

## 8. Document it

* [`configuration.md`](configuration.md) — a `[mako]` section and the component
  in the `[components]` table.
* [`themes.md`](themes.md) — only if you added a theme field.
* [`deployment.md`](deployment.md) — the reload behaviour, and the managed path
  if it is not the obvious one.

---

## Checklist

```text
[ ] config struct, Components flag, Enabled, Names, Any
[ ] defaults
[ ] template, with a generated-by header
[ ] adapter: Name, Files, ConfigPaths, ReloadMode, Validate
[ ] reload command, if it has one
[ ] registered in app.go and the three test registries
[ ] program fields in session/programs.go
[ ] preview entry in session/sandbox.go
[ ] make golden, and read the diff
[ ] docs
```
